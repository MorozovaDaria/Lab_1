Отчёт по лабораторной работеВведение в ООП: создание классов, конструкторов, методов, наследование. Паттерны «Фабричный метод» и «Итератор»1. Цель работыОсвоить основы объектно-ориентированного программирования (классы, наследование, контейнеры) на примере системы управления орбитальной станцией и её модулями.

Реализовать паттерны «Фабричный метод» / «Абстрактная фабрика» для создания модулей, а также обеспечить возможность итерации по модулям станции.Язык реализации: C++.2. Текстовое описание архитектурыСистема состоит из следующих основных частей:Классы-атрибуты:
Durability — прочность модуля (целое число ≥ 0). Имеет методы getValue, setValue, decrease, repair.
EnergyConsumption — энергопотребление (целое число ≥ 0). Имеет методы getValue, setValue, increase, decrease.
Capacity — вместимость (целое число ≥ 0). Имеет методы getValue, setValue.
Иерархия модулей:
Абстрактный базовый класс Module
Содержит общие поля: ID_, name_, effectiveness_, condition_, а также объекты Durability, EnergyConsumption, Capacity.
Объявлены чисто виртуальные методы clone() и getType().
Реализованы методы activate(), deactivate(), setState(), setEffectiveness(), moveToIndex().
Промежуточные классы:
ApartmentModule (жилые модули)
EnergyModule (энергетические модули)
ResearchModule (исследовательские модули)

Конкретные классы:
Жилые: CrewCabin, MedicalCabin
Энергетические: SolarModule, ReactorModule
Исследовательские: BiologyLab, PhysicsLab

Каждый конкретный класс переопределяет clone() и getType().Фабрики:
Абстрактный класс ModuleFactory с чисто виртуальными методами:
createApartmentModule(...)
createEnergyModule(...)
createResearchModule(...)

Конкретные фабрики:
StandardModuleFactory — создаёт CrewCabin, SolarModule, BiologyLab
AdvancedModuleFactory — создаёт MedicalCabin, ReactorModule, PhysicsLab

Класс Station (склад/станция):
Хранит модули в std::vector<std::unique_ptr<Module>>
Имеет ограничение максимального количества модулей (maxModules_)
Реализованы методы добавления, удаления по ID и по индексу, поиска по ID
Реализовано правило пяти (конструктор копирования, оператор присваивания копированием, конструктор перемещения, оператор присваивания перемещением, деструктор)
Глубокое копирование выполняется через вызов clone() у каждого модуля
Поддерживается итерация через begin() / end() и метод getIterator()
Реализован метод moveModule для изменения позиции модуля внутри станции
Связи:
Station владеет модулями через unique_ptr
Module содержит объекты атрибутов по значению
Конкретные модули наследуются от промежуточных категорий, которые наследуются от Module
Фабрики создают объекты модулей и возвращают указатель на базовый класс Module*
3. Реализация паттерна «Фабричный метод» / «Абстрактная фабрика»Паттерн реализован следующим образом:
Создан абстрактный класс ModuleFactory с тремя чисто виртуальными методами создания модулей разных категорий.
От него наследуются две конкретные фабрики:
StandardModuleFactory
AdvancedModuleFactory

Каждая фабрика отвечает за создание своего «семейства» модулей.

Клиентский код (main) работает только с указателем/ссылкой на ModuleFactory и не зависит от конкретных классов модулей. Это позволяет легко добавлять новые типы модулей и новые фабрики без изменения кода станции.4. Реализация итератораДля обхода модулей станции использованы стандартные итераторы контейнера std::vector через методы:
begin() / end()
begin() const / end() const
дополнительно добавлен метод getIterator()
Благодаря этому поддерживается range-based for:C++for (const auto& module : station) {
    // работа с модулем
}Это соответствует требованию задания о предоставлении возможности итерации по модулям (адаптация стандартного итератора + явный метод получения итератора).5. Правило пяти в классе StationВ классе Station явно реализованы все пять специальных функций-членов:
Конструктор копирования — выполняет глубокое копирование всех модулей через вызов clone().
Оператор присваивания копированием — очищает текущее содержимое и создаёт глубокие копии модулей.
Конструктор перемещения — перемещает вектор модулей (std::move).
Оператор присваивания перемещением — перемещает ресурсы.
Деструктор — оставлен по умолчанию, так как unique_ptr автоматически освобождает память.
Это обеспечивает корректное управление ресурсами и предотвращает поверхностное копирование указателей.6. Результаты демонстрационных сценариевПри запуске программы выводится:textСценарий 1: Создание станции и добавление модулей
